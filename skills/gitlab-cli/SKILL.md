# GitLab CLI (glab)

Command-line tool for GitLab. Requires prior `glab auth login` setup.

## Authentication

```bash
glab auth login                    # Interactive login (OAuth or token)
glab auth status                   # Check authentication status
```

Environment variables:

- `GITLAB_TOKEN` - API token (overrides stored credentials)
- `GITLAB_HOST` - Self-managed GitLab URL (default: gitlab.com)

## Quick Reference

```bash
# Merge Requests
glab mr list                       # List open MRs
glab mr list --assignee=@me        # My assigned MRs
# Create MR with explicit title/description (preferred)
glab mr create -t "PROJ-123: Title" -d "Description" --remove-source-branch
glab mr view 123 -F json           # View MR details as JSON
glab mr merge 123                  # Merge MR
glab mr checkout 123               # Checkout MR branch locally

# Issues
glab issue list                    # List open issues
glab issue list --assignee=@me     # My assigned issues
glab issue create -t "Title"       # Create issue
glab issue view 123                # View issue details

# CI/CD
glab ci status                     # Current branch pipeline status
glab ci view                       # Interactive pipeline viewer
glab ci retry <job-id>             # Retry failed job

# Repository
glab repo view                     # View repo info
glab repo clone owner/repo         # Clone repository
```

## Cross-cutting gotchas

- Use `-d`/`--description`, **not** `--body` (that's a `gh`-ism).
- Use `-b`/`--target-branch`, **not** `--base`.
- Output flags are command-specific: `glab mr list -F json`, but
  `glab issue list -O json`. Check `--help` when scripting.
- After creating/updating an MR, **always verify the description** with
  `glab mr view <MR_ID> -F json | jq -r '.description'` and strip any
  autogenerated noise. See `references/merge-requests.md`.
